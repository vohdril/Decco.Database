## Anomaly
 
ROOT ENTITY. Each row is a record of the DeCCO anomaly catalog. It gathers the ontological classification (class, layer, matter, mechanisms), the Brazilian classification (cognition, dangerousness), the measurable Theta markers and the operational state. Id starts at 1000; the public identity is ScpCode.
 
| Column | Type | Nullable | Description |
|---|---|---|---|
| `Id` | int | no | Internal Id, IDENTITY starting at 1000. It is NOT the public identity — the contract exposes ScpCode (IdToCode pattern). |
| `ScpCode` | varchar(50) | no | Public, stable identity of the anomaly (e.g. SCP-1001). External consumers reference the record by this code. |
| `CommonName` | nvarchar(255) | no | Common name, readable by operators (e.g. Proteu - O Metamorfo Complexo). |
| `Description` | nvarchar(MAX) | no |  |
| `ObjectClassId` | int | no | Containment class. Through Cat_ObjectClass.MinClearanceLevel, it determines the clearance needed to see this anomaly. |
| `OntologicalLayerId` | int | no | Plane the anomaly operates on (THETA/PSI/PHI/OMEGA). Together with the matter type, it defines whether it falls into the Sigma slice. |
| `MatterTypeId` | int | no | Material composition. Non-baryonic matter resists Theta suppressors and raises the Sigma flag. |
| `ApparentCognitionId` | int | yes | Brazilian cognition classification (SE/SA/IN/AA). Null until measured. |
| `DangerLevelId` | int | yes | Brazilian dangerousness classification (1..9). Null until measured. |
| `PrimaryMechanismId` | int | no | Main VISIBLE mechanism — the observable HOW of the phenomenon (e.g. transformation = THETA-C). |
| `SecondaryMechanismId` | int | yes | Underlying mechanism, optional. Only accepts mechanisms flagged as a sub-nature, and OMEGA cannot have a THETA sub-nature — both rules enforced by TR_Anomaly_ValidateMechanisms. |
| `IeiaDBaseline` | decimal(8,4) | yes | Anomalous Isotopic Enrichment Index for Deuterium, measured on the object itself. The human baseline is below 0.015%; above 0.1% indicates active use of the Theta layer. It is the central quantitative marker of the system. |
| `SpinCoherenceFactor` | varchar(20) | yes | Degree of anomalous spin coherence, on a textual scale: Nulo, Baixo, Médio, Alto, Crítico. Crítico indicates a Frozen Spin pattern coupled to a higher layer. |
| `Status` | varchar(20) | yes | State of the RECORD: ATIVA, NEUTRALIZADA, DESTRUIDA. NOTE: the EM_PESQUISA value, used today, is a WORKFLOW state, not a catalog state — it moves to the classification pipeline once that exists (DECCO-BACKLOG, finding 6). |
| `ResearchLead` | nvarchar(255) | yes | Responsible researcher, as free text. It is a PROCESS attribute, not a catalog one. The Operation entity exists since 0003; moving this data to Operation.ResponsiblePerson (PESQUISA type) is the next step, recorded in DECCO-BACKLOG. |
| `CreatedAt` | datetime | yes |  |
| `UpdatedAt` | datetime | yes | Maintained automatically by TR_Anomaly_SetUpdatedAt on every UPDATE. Facility and Operation follow the same pattern (TR_Facility_SetUpdatedAt, TR_Operation_SetUpdatedAt); the baseline tables do not. |
| `CreatedBy` | nvarchar(128) | yes | Filled with SYSTEM_USER by DEFAULT. In the baseline, Anomaly was the only table with user auditing; Facility and Operation are born with it. The other baseline tables only have dates (DECCO-BACKLOG, finding 5). |
| `UpdatedBy` | nvarchar(128) | yes | Updated by TR_Anomaly_SetUpdatedAt with SYSTEM_USER on every UPDATE. |
| `ContainmentFacilityId` | int | yes | Where the anomaly is physically contained: the most specific known facility (containment area or laboratory; otherwise, the site). Replaced the free-text SitioContencao (migrations 0002/0004). It is NOT a permission boundary: the anomaly is a global catalog, sliced by clearance; what is sliced by facility is Operation. |
